# Log Feature Request

사용자로부터 새로운 아이디어나 기능 요청을 받았을 때, 프로젝트의 문서에 체계적으로 기록하는 스킬입니다.

## Workflow

1. **아이디어 분석**:
   - 사용자가 제안한 아이디어/기능 요청의 핵심 내용을 파악합니다.
   - 이것이 완전히 새로운 기능인지, 기존 기능의 개선인지 판단합니다.

2. **문서 확인 (`read_file`)**:
   - `docs/01-ideas.md` 파일을 읽어 현재 아이디어 목록과 카테고리 구조를 파악합니다.
   - 필요하다면 연관된 기획 문서(`docs/02-product-spec.md` 등)도 함께 확인합니다.

3. **기록 위치 결정**:
   - 기존의 카테고리(예: 필수, 선택, 아이디어 뱅크 등) 중 어디에 속하는지 결정합니다.
   - 적절한 카테고리가 없다면 "추가 제안" 또는 유사한 섹션에 배치합니다.

4. **문서 업데이트 (`replace` 또는 `write_file`)**:
   - 기존 문서의 포맷(Markdown 리스트, 제목 등)을 준수하여 새로운 아이디어를 추가합니다.
   - 아이디어의 제목, 간략한 설명, 그리고 기대 효과나 임팩트를 포함하여 기록합니다.
   - 카테고리 제목에 항목 개수(예: "필수 (Must) 8개")가 명시되어 있다면, 새 항목을 추가하면서 해당 숫자도 알맞게 업데이트합니다.

5. **사용자 피드백**:
   - 문서 업데이트가 완료되면, 사용자에게 어떤 카테고리에 어떻게 기록했는지 간략히 보고합니다.

## Best Practices

- **일관성**: 기존에 작성된 글투와 포맷(예: 굵은 글씨 제목, 화살표(`→`)를 사용한 설명 등)을 그대로 유지하세요.
- **간결함**: 아이디어는 너무 길지 않게 핵심만 요약해서 기록하세요.
- **문맥 고려**: 기존 아이디어들과 중복되는 경우, 새로운 항목으로 추가하기보다 기존 항목을 수정/보완하는 방향을 고려하세요.
