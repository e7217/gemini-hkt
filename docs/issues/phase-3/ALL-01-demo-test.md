## 구현 범위
1. **데모 시나리오 전체 검증** (3분 시나리오):
   - **ACT 1 (30초)**: "누구나 시작할 수 있다"
     - 🎲 클릭 → "풀스택 개발자 되기" 자동 채움 → "경로 생성하기" 클릭
     - 로딩 애니메이션 표시 → 경로 맵 전환
   - **ACT 2 (50초)**: "당신의 나무가 자랍니다"
     - 3경로 수직 맵 표시 확인
     - 타임라인 슬라이더 1년 → 3년 → 5년 확장
     - 노드 점진적 등장 확인
   - **ACT 3 (30초)**: "어떤 길이든 괜찮다"
     - 합류점 노드 시각적 확인 (다색 그라데이션)
     - 노드 클릭 → 상세 패널 표시
     - 트랙 하이라이트 동작
   - **ACT 4 (10초)**: 마무리 화면
2. **Plan A / Plan B 전환 테스트**:
   - Plan A: 라이브 Gemini API 정상 동작 확인
   - Plan B: USE_MOCK=true로 전환 시 Mock 데이터 정상 표시
   - 전환 시 UI 차이 없음 확인
3. **3회 연속 성공 확인**:
   - 동일 시나리오 3회 반복
   - 매회 안정적 동작
   - 에러/버그 없음
4. **성능 확인**:
   - API 응답 시간 (타임아웃 15초 이내)
   - 맵 렌더링 속도 (3초 이내)
   - 슬라이더 반응 속도 (300ms 이내)

## 아이디어 뱅크 제안

- **"관객 참여형" 오프닝 연출**: 데모 시작 시 "여기 계신 분 중 진로 고민해보신 분?" 질문 후, 관객에게 목표를 직접 말하게 하고 실시간 입력. 사전 준비된 랜덤이 아닌 실시간 생성을 보여주면 기술력과 범용성을 동시에 증명. Plan B로 사전 캐싱 데이터 준비해두면 안전.

- **ACT 2에서 "일시정지" 연출**: 경로 애니메이션 중 의도적으로 한 번 멈추고, "지금 이 분기점에서 여러분이라면 어떤 길을 선택하시겠어요?" 관객에게 질문. 1~2초 침묵 후 클릭. 수동적 관람을 능동적 참여로 전환하는 프레젠테이션 기법.

- **"Golden Path" 사전 녹화**: 가장 이상적인 데모 흐름을 사전에 1회 화면 녹화. Plan C(전체 영상)가 아닌, 특정 구간이 불안정할 때 "잠깐, 이 부분을 좀 더 자세히 보여드리겠습니다"라며 자연스럽게 녹화 영상으로 전환하는 Plan B+.

- **"숫자로 말하기" 전략**: 데모 테스트 중 측정한 숫자를 발표에 활용. "6시간 동안 Gemini가 생성한 경로 노드 수: XX개, 합류점: XX개, 가능한 인생 시나리오: XX가지" 같은 구체적 숫자는 기술적 완성도의 증거.

- **마지막 한 마디 강화**: ACT 4 마무리에서 합류점을 가리키며 "LifePath가 증명합니다 -- 어떤 길을 선택해도, 우리는 결국 만납니다." 합류점이라는 기술 구현과 감성 메시지를 직접 연결하는 클로징.
