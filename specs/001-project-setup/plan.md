# Implementation Plan: BE-01 프로젝트 초기 세팅

**Branch**: `001-project-setup` | **Date**: 2026-02-27 | **Spec**: [spec.md](./spec.md)
**Input**: Feature specification from `/specs/001-project-setup/spec.md`

## Summary

Initialize the LifePath project with Next.js 14+ App Router + TypeScript (strict mode), configure Tailwind CSS and shadcn/ui (dark mode default), install React Flow v12 (`@xyflow/react`) + dagre (`@dagrejs/dagre`) for path visualization, install Zustand for state management, create the standard directory structure, and configure environment variable files. This setup is the prerequisite for all BE and FE features and must be completed first (hackathon 0:00–0:20 window).

## Technical Context

**Language/Version**: TypeScript 5.x (strict mode), Node.js >=18
**Primary Dependencies**:
- `next@14+` (App Router)
- `react@18`, `react-dom@18`
- `tailwindcss`, `postcss`, `autoprefixer`
- `shadcn/ui` (CLI-based component generation)
- `next-themes` (dark mode class strategy)
- `@xyflow/react@^12.0.0` (React Flow v12)
- `@dagrejs/dagre` (graph layout)
- `zustand` (state management)
- `@types/dagre` (TypeScript types for dagre)

**Storage**: No database in this phase — client state only (localStorage for anonymous session)
**Testing**: TypeScript compiler (`tsc --noEmit`) for type-checking; `npm run dev` smoke test
**Target Platform**: Vercel (serverless, Edge-compatible Next.js deployment)
**Project Type**: Web application (Next.js monorepo — App Router handles both frontend pages and backend API routes)
**Performance Goals**: Dev server cold start <30s; production build completes without error
**Constraints**: Must use `@xyflow/react` v12 (not legacy `reactflow`); dark mode must be class-based (not media query) for programmatic control; API key must never be exposed to client bundle
**Scale/Scope**: Single-developer hackathon setup; ~6 source files and 6 directories created in this phase
